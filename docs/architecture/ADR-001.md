# ADR-001 — Arquitectura objetivo

Estado: propuesta de implementación basada en el roadmap aceptado; decisiones de producto confirmadas en `../requirements/DECISIONS.md`.

## Contexto

La consola tiene 33 fuentes Java y acopla archivos, interacción, autenticación y compra. Migrar de manera incremental permite comprobar las reglas antes de reemplazar la interfaz. Spring sigue pendiente. La primera infraestructura Oracle se implementó en `infra/oracle` y se verificó con dos PDB.

## Decisión

Monolito modular Java 25 con Spring Boot, frontend React/TypeScript y Oracle en Docker Compose para desarrollo. Fijar versiones compatibles y dependencias en el hito técnico correspondiente. Spring Boot 4.1.1 declara soporte hasta Java 26, por lo que Java 25 cabe en su rango.

Módulos objetivo: identidad, organizaciones, cartelera, reservas, ventas, inventario, personal, lealtad, reportes, simulación y asistente. No deben convertirse automáticamente en doce artefactos Maven: empezar como paquetes con límites y pruebas de dependencia.

Dentro de cada módulo:

- Dominio: reglas y objetos de valor, sin UI ni persistencia.
- Aplicación: casos de uso y límites transaccionales.
- Infraestructura: Oracle, HTTP, archivos heredados y proveedores externos.

La web consume los casos de uso mediante API. Autorización en backend para cada operación, no solo ocultando botones. Para un despliegue web del mismo origen, evaluar sesiones de servidor con cookies HttpOnly/Secure y protección CSRF antes de adoptar JWT por defecto.

## Oracle Multitenant

Prototipo objetivo: una CDB con PDB CINE_TICS y PDB CADENA_DEMO. CU, Universidad, Delta y Xochimilco pertenecen a CINE_TICS. Oracle Multitenant y aislamiento SaaS requieren controles separados.

- Validar imagen ARM64, versión fija/digest, límites de PDB y recursos antes de escribir el Compose definitivo.
- Resolver tenant desde identidad autenticada y membresía autorizada, nunca aceptar sin validación un encabezado o ID recibido del cliente.
- Pool/conexión y usuario de aplicación propios por PDB, sin permisos de administración de CDB.
- Migraciones versionadas por PDB; no reutilizar un pool con estado de tenant de una petición anterior.
- Pruebas con dos cadenas y datos de igual identificador: lectura, escritura, reportes y tareas en segundo plano no deben cruzarse.
- Volumen persistente, healthcheck y verificación de reinicio; procedimientos reales de respaldo y restauración.
- Free se evalúa para demo/desarrollo. Antes de producción revisar soporte, recursos y edición. No asumir crecimiento ilimitado de PDB ni equivalencia entre edición Free y una instalación comercial.

## Integridad comercial

- Dinero con BigDecimal, moneda MXN y redondeo acordado.
- Disponibilidad por **función y asiento**, no solo por sala física.
- Reserva temporal con vencimiento; restricción/operación atómica para evitar doble venta.
- Cantidades positivas y stock no negativo; comprobar y actualizar dentro de la transacción.
- Compra con estados, identificador idempotente y resultado persistente.
- Pago simulado aprobado antes de confirmar venta/puntos/consumo de inventario. Un fallo debe dejar un estado recuperable, sin ticket de venta exitosa.
- Al añadir una pasarela real, definir conciliación y compensaciones; una transacción SQL no hace atómica una llamada externa.

## Patrones aplicados cuando haya necesidad

Repository/Adapter para persistencia y proveedores; Strategy para políticas de lealtad/precio; máquina de estados para compra/pedido/simulación; eventos de dominio posteriores a confirmación para alertas. Usar outbox solo cuando se necesite entrega durable fuera del proceso. Evitar event sourcing y microservicios en esta primera versión.

## Rob y S.I.G.A.

S.I.G.A. orquesta pedidos y simulación mediante casos de uso comprobables. Rob consulta esas capacidades y la disponibilidad real. Ningún modelo de IA decide precios, permisos, saldo o confirmación de compra. Antes de añadir IA debe existir búsqueda determinista y el backend debe validar todas las acciones.

## Consecuencias

Un único backend simplifica desarrollo y despliegue. PDB por cadena aumenta aislamiento, pero también el coste de aprovisionar, migrar y mantener conexiones. Esta decisión se revisará después del prototipo Oracle y de las pruebas de aislamiento.

## Implementación inicial de Oracle

Imagen oficial ARM64 `23.26.3.0-lite-arm64`, Flyway 13.8.0, controlador ojdbc11 23.7.0.25.01. Existen CINE_TICS y CADENA_DEMO además de FREEPDB1; esquema CINE_OWNER y usuario CINE_APP por PDB. No hay aún resolución de tenant en la aplicación web ni importación de datos históricos.
